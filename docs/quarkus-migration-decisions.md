# Quarkus migration: decisions log (run-01, Spring compatibility strategy)

Working notes, kept so the decisions survive between phases. The final write-up is `migration-report.md`.

| # | Decision | Reason / trade-off |
|---|---|---|
| D1 | `openapi-generator` switched from `spring` to `jaxrs-spec` (interfaceOnly, returnResponse). Controllers become JAX-RS resources returning `jakarta.ws.rs.core.Response`. | `quarkus-spring-web` only maps `@RestController` classes that declare their own `@RequestMapping`/`@GetMapping`. The controllers inherited those from generated interfaces, which the compat processor ignores. Hand-copying the OpenAPI mapping annotations into 8 controllers would duplicate the contract. The REST layer is therefore "full Quarkus" (hybrid with the compat strategy). |
| D2 | `quarkus-spring-web` removed. `ExceptionControllerAdvice` rewritten with `@ServerExceptionMapper` methods. | The advice depends on `HttpServletRequest`, `ProblemDetail` and `MethodArgumentNotValidException`, none available in compat. With D1 no Spring MVC annotation is left, so the extension is unnecessary. |
| D3 | Kept compat extensions: `quarkus-spring-di` (`@Service`, `@Autowired`, `@Transactional` are still used in `service/**`), `quarkus-spring-tx`, `quarkus-spring-data-jpa` (only for the `Page`/`Pageable`/`PageImpl` types via `quarkus-spring-data-commons-api`). | 1:1 mappings for the service layer. Service beans are annotated `@ApplicationScoped` (a normal scope) so they can be mocked with `@InjectMock`; `@Service` yields a `@Singleton`, which Quarkus cannot mock. |
| D4 | **Repository layer: the plain-JPA implementations (`repository/jpa/Jpa*RepositoryImpl`, `EntityManager` based) are the active persistence layer.** `repository/springdatajpa/**` and `repository/jdbc/**` are excluded from compilation (files kept, with TODO). `@Repository` -> `@ApplicationScoped`, `@PersistenceContext` -> `@Inject`, `@Profile` removed. | The `quarkus-spring-data-jpa` 3.40.1 processor cannot handle the project's two-level design (`XRepository` + `SpringDataXRepository` + `*Override` fragments): it treats non-Spring-Data parents as fragments needing `*Impl` classes, cannot derive `save(Entity)`/`delete(Entity)` ("no proper 'By' clause") and fails with "Duplicate method added" on `@Override` redeclarations. Every variant tried failed. Rewriting the Spring Data layer was out of scope; the plain-JPA layer already existed and passes the same 36 service tests. `JdbcTemplate` has no compat extension. Trade-off: the runtime repository-layer choice (`spring.profiles.active=...,jpa/jdbc/spring-data-jpa`) is gone. |
| D5 | Spring Security config (`security/BasicAuthenticationConfig`, `DisableSecurityConfig`) excluded from compilation, `@PreAuthorize` annotations kept as TODO comments. `quarkus-spring-security` removed. | `hasRole(@roles.X)` is not in the supported SpEL subset, and `HttpSecurity`/`SecurityFilterChain` have no equivalent. Security is disabled by default (`petclinic.security.enable=false`), so default behaviour is preserved. **Runtime risk:** with `petclinic.security.enable=true` there is currently no authentication. |
| D6 | HSQLDB profile and H2 console not supported. | No Quarkus JDBC extension for HSQLDB; no H2 console. |
| D7 | Schema comes from Hibernate (`drop-and-create`) + `sql-load-script` (data.sql) instead of `schema.sql` + `data.sql`. | Quarkus has no `spring.sql.init.*`. Change to `none`/`validate` for persistent databases. |
| D8 | `<generateJsonCreator>false</generateJsonCreator>` in the openapi-generator config. | Without it the `jaxrs-spec` `@JsonCreator` constructors treat read-only `id` as required, so POST of specialties, visits etc. returned 400. |
| D9 | CORS: `@CrossOrigin` (which allowed all origins) replaced by a global allowlist (`PETCLINIC_CORS_ORIGINS`, default `http://localhost:4200`). | Quarkus has no per-class `@CrossOrigin`. A wildcard origin would violate the project security rules. |
| D10 | `quarkus.http.host` defaults to `127.0.0.1` (`PETCLINIC_HTTP_HOST` overrides it). | Quarkus binds to 0.0.0.0 in prod by default; the project security rules forbid that. For containers set the variable explicitly. |
| D11 | `CallMonitoringAspect` (AspectJ + Spring JMX) excluded from compilation, kept with TODO. | No compat equivalent; could become a CDI interceptor later. |
| D12 | `logback.xml` removed. Its single logger setting is in `application.properties`. | Quarkus uses JBoss Log Manager and ignores Logback configuration. |
| D13 | `PersistenceException` (was `DataIntegrityViolationException`) is mapped to the same 404 "data constraint violation" response. Validation error `title` is now `ResteasyReactiveViolationException` (was `MethodArgumentNotValidException`). | Spring exception types do not exist at runtime any more. The response shape (`application/problem+json`) is unchanged. |
| D14 | `OopsApi` (`/api/oops`) has no implementation. | The Spring code had none either (404). |
| D15 | Tests: MockMvc controller tests (8 classes) converted to `@QuarkusTest` + REST-Assured + `@InjectMock ClinicService`/`UserService`. Service tests use `@TestTransaction`. `AbstractClinicServiceTests` and `AbstractUserServiceTests` keep a single JPA subclass. `ValidatorTests` uses `Validation.buildDefaultValidatorFactory()`. `assertj-core` 3.27.7 added as test dependency (it was transitive in `spring-boot-starter-test`). | The jdbc/hsqldb/spring-data-jpa test variants test layers that are parked; those files are kept with TODO and listed in `testExcludes`. `src/test/resources/application.properties` (Spring profile config) removed; Quarkus uses `application.properties` with its default (H2) test configuration. |
| D16 | `Roles.java` (Spring `@Component`, only referenced from `@PreAuthorize` SpEL which is parked) left unchanged. | Needed again when `@PreAuthorize` is re-enabled (D5). |
| D17 | Coverage measurement: added the `io.quarkus:quarkus-jacoco` test dependency. `jacoco-maven-plugin` keeps `prepare-agent`, `check` and `report`, with `exclClassLoaders=*QuarkusClassLoader`, `destFile`/`dataFile` = `target/jacoco-quarkus.exec` and `append=true`. Thresholds (85% lines, 66% branches) unchanged. | `@QuarkusTest` loads the application through the `QuarkusClassLoader`, which the plain JaCoCo agent does not record; `mvn verify` failed with 10% / 5% coverage. See `docs/test-coverage.md`. |
| D18 | Added `MapperNullSafetyTests` (1 test, 7 generated MapStruct mappers). | The gate was 1 line and 5 branches short after D17, because the JDBC / Spring Data JPA service tests that used to reach the mapper null-guards are parked. Preferred to lowering the thresholds. Limited value; see section 5 of the coverage report. |
