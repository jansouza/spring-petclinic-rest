## Main risks

- The generated `*Api` interfaces are built with the Spring generator. For the full Quarkus path, the generator would have to switch to `jaxrs-spec`.
- The three-way repository selection by Spring profile has no direct Quarkus equivalent. It would need `@IfBuildProperty`/`@LookupIfProperty` or a decision to keep only one implementation.
- Spring Boot 4.x with Jackson 3 (`tools.jackson`) needs care when moving to Quarkus.

## Strategy options

1. **Spring compatibility** (recommended): use `quarkus-spring-web`, `quarkus-spring-data-jpa`, `quarkus-spring-di`, `quarkus-spring-security` and similar. This changes the least code and keeps most Spring annotations.
   - Limits: the Spring MVC compat layer covers only part of `ResponseEntity`, `@ControllerAdvice` and `UriComponentsBuilder`. The generated Spring interfaces and the Spring JDBC repositories (`JdbcTemplate`) have no compat extension and need manual work.
2. **Full Quarkus**: JAX-RS, CDI, Panache or Hibernate ORM, and Quarkus Security. This gives the full Quarkus experience but needs much more work, including switching the generator to `jaxrs-spec` and rewriting the repositories and tests.

**Decision:** pending (strategy not chosen yet).
